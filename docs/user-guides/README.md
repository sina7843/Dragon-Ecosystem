# Dragon Ecosystem — Persian documentation package

Produced by DRAGON-30. Everything here is generated or verified against the running product;
nothing is hand-asserted about a route, permission, gate or provider.

## What is in here

| File | What it is | Maintained by |

| `dragon-complete-guide-fa.html` | Responsive RTL web version | `guide:build` |

## Commands

```bash
npm run guide:inventory   # extract the product surface from source
npm run guide:capture     # drive the running product, take figures, record what was observed
npm run guide:build       # expand tables, then emit md / html / docx / pdf
npm run guide:verify      # structural, content, secret and visual checks; exits non-zero on failure
npm run guide             # inventory -> build -> verify (no capture; reuses existing figures)
```

`guide:capture` needs the disposable test database (`npm run db:test:up`) and a current build
(`npm run build`). It starts its own API and preview server on separate ports and its own
database, so it never disturbs the product test suite.

## How the pipeline avoids lying

- **Facts are extracted, not typed.** Routes, roles, permissions, gates and environment
  variables come from `SITE_INVENTORY.json`, which is parsed from source. The extractor
  accounts for every route registration and fails if an expansion it relies on goes stale.
- **Figures record what happened.** Each capture writes the state it observed —
  `available`, `permission-required`, `feature-gated`, `provider-unavailable` — so a blocked
  flow is documented as blocked rather than omitted.
- **The capture environment matches the shipped defaults.** It deliberately does *not* reuse
  the product test configuration, which forces `PAID_TOURNAMENTS_ENABLED` and
  `PAID_COURSES_ENABLED` on. It also asserts `paidCoursesEnabled === false`,
  `provider === 'stub'` and `rightsPolicyApproved === false` before capturing the figures that
  document those states.
- **Secrets cannot reach a figure.** The capture step scans the rendered page and fails the
  run rather than saving a screenshot containing a token, cookie, key or signed URL. Mobile
  numbers and long opaque identifiers are masked before the shot.
- **The PDF is inspected, not assumed.** `guide:verify` reads page geometry and fonts out of
  the file and renders representative pages to images through the platform's own PDF renderer.

## Conversion tooling

DOCX is produced directly as WordprocessingML by `scripts/guide/lib/docx.mjs` (no third-party
package), and converted to PDF by the locally installed Word through COM. No external
document-generation service is used, and no font files are added to the repository — the
manual uses Tahoma, which ships with Windows and covers Persian.

**Deviation worth knowing:** the task described authoring in DOCX and converting to PDF. There
is no local DOCX authoring or conversion tool other than Word itself, and a binary source
cannot be reviewed in a pull request. The source of truth is therefore Markdown, and DOCX is
generated from it — the DOCX and PDF deliverables are still produced, and the conversion to
PDF is still Word's.

## Scope

This package documents the platform; it does not change it. One confirmed product defect is
recorded in `TRAINING_AND_UX_FINDINGS.md` (F-01, no role-assignment UI) and deliberately left
unfixed — remediation belongs to a separate slice.
